*inkstone* *inkstone-japanese*  Japanese layout and Inkstone-specific behavior

Use |inkstone.txt| for inherited configuration and API reference.

Nightly conceal-aware wrap automatically applies to persistent extmark and
Tree-sitter conceal. Bounded native text-height measurement plans viewports
when supported; older APIs retain the existing source-row fallback. BudouX
source-boundary selection also accounts for native Tree-sitter conceal when
supported, while keeping original source positions. List display and splits
showing different buffers retain BudouX wrapping.

SETUP
>
  require('inkstone').setup({
    pipe_table = {
      cell = 'trimmed',
      wrap = true,
      japanese = { enabled = true, budoux = true },
    },
    paragraph = { wrap = true, join = false, japanese = { enabled = true, budoux = true } },
  })
<
BudouX is bundled and runs offline. Japanese table wrapping prefers phrase
boundaries and basic forbidden-start/forbidden-end character rules. If a column
is too narrow to satisfy kinsoku, the width bound takes priority. Set
japanese.budoux=false to keep kinsoku without phrase segmentation; set
enabled=false to disable both Japanese boundary policies.

LUA API
>
  local text = require('inkstone.text')
  local phrases = text.segment('今日は天気がいいから散歩しましょう。')
  local lines = text.wrap('「日本語」の表を、読みやすく。', 12)
<
The API returns strings without editing any buffer. Width follows Neovim's
strdisplaywidth(). Top-level paragraphs use this layout by default. Source
newlines are preserved and each long line wraps independently. Set
paragraph.join=true to join soft source newlines; explicit Markdown hard breaks
always remain. With join=false, inline whitespace guides native wrapping while
source rows stay visible. Use gj/gk, g0/g$, character selection and yank normally;
g0yg$ yanks a screen row, yy the original logical line. Padding never enters
registers or saved text. Anti-conceal does not remove native wrap padding.
Visual follows render_modes. Ordinary defaults omit v, V and CTRL-V, so entering
Visual temporarily shows raw Markdown and source wrapping; Normal restores the
rendered view. Explicit Visual entries or render_modes=true keep decorations.
Native paragraphs with normal-mode rendering preserve the normal view during
pending operators and command/search input even if render_modes omits those
modes. Accepting/canceling :, / or ? does not clear
decorations or reset conceal/wrap options. Anti-conceal still uses the actual
selection range.
Inkstone temporarily disables linebreak for this layout and restores the
previous window setting when it stops. Explicit win_options.linebreak overrides
this policy. Shared windows, nowrap/list, tabs/control characters, unsupported
indent options and additional inline virtual text use ordinary source wrapping.
See doc/rendering-features.md, "Japanese paragraph layout", for the full limits.
With join=true, virtual rows are used; anti_conceal's cursor range restores the
whole source paragraph. The wrap and join flags are independent; both false use
Neovim's ordinary source wrapping. Defaults are wrap=true, join=false.

Tables with wrapped replacement rows restore the whole source table when
anti_conceal's cursor range overlaps it. Borders and inline decorations return
when the cursor leaves. With anti_conceal.enabled=false, rendered typography,
joined paragraphs, table/list/chart views and math blocks remain visible under the cursor; source
wrap/nowrap behavior remains visible while editing.
Nested list/quote paragraphs, image anchors and converted math keep source rows.

MEDIA AND FOLDS
:Inkstone media opens the image/diagram at or before the cursor in a floating
view. + / - zoom; hjkl pan; 0 fits; [ / ] change PDF page; q or Escape close it.
Ordinary PDF links and #page=N are recognized. The viewport needs ImageMagick,
and PDFs also need its Ghostscript delegate. Images use the optional Snacks image backend. Mermaid and
PlantUML conversion additionally require the local mmdc/plantuml executables.
Conversion runs asynchronously; missing dependencies leave readable source.
Use :checkhealth inkstone and :checkhealth snacks to inspect dependencies.

:Inkstone toggle_fold toggles the containing code block, callout or details.
<Plug>(InkstoneToggleFold) can be mapped without replacing existing keybindings.
The side preview maps za and <CR> to toggle_view. Callout [!NOTE]- and details without open start
collapsed; code blocks start expanded. Source bytes and foldmethod are unchanged.
Set folds.enabled=false or media.enabled=false to disable these features.
Images inside padded/trimmed wrapped tables fit their cell width and
media.max_height. Captions and vertical borders share the image rows. This
requires a Snacks Unicode-placeholder backend and one window for the buffer.
Resizing refits the cells; source restoration and list/chart views remove the
cell images. Native Snacks document images outside these tables stay native.
GIF/video previews depend on installed converters; playback is not provided.
Blank lines between details and summary tags are supported. Toggling from a
hidden child opens its collapsed parent first.
Code folds inside details are independent and keep their state across parent
close/reopen. Ctrl+i on code toggles code; use the details title for the parent.
Fold triangles always stay left (▶ closed / ▼ open), beside title/language.
folds.position='right' shows "▶ Summary N lines", with one space after the label.
It follows the label rather than aligning to the window edge. Details/callouts retain counts
in both states; code shows fold controls only while collapsed.
Use folds.position='left' for "▶/▼ N lines · title/language".
Callout counts use the same position; code.position controls ordinary code labels.
InkstoneFoldIcon follows Comment colors with GUI/cterm italic disabled.
Expanded code uses its ordinary language header; reopening retains decoration
at the cursor. Newly visible
code after a long closed fold renders without a scroll; hidden bodies stay out
of the render viewport.
Anti-conceal margins around the anchor do not reopen collapsed bodies.
Details/summary tags become a styled header, with InkstoneDetailsHeader (Title)
and InkstoneDetailsBody (NormalFloat). Multiline summaries are supported.
The body renders Markdown even without blank separators; no HTML parser is
required. Fenced HTML examples stay literal. Use the standard <details> tag.
Code colors require the language parser; common aliases such as sh, py and js
are recognized without replacing user registrations. Without a native
highlighter, code.syntax=true colors visible code from its injection trees.
Set code.syntax=false to disable this fallback. Indented code receives block
background/padding; open fences and EOF keep their final body row decorated.
<Plug>(InkstoneMoveDown) and <Plug>(InkstoneMoveUp) skip hidden fold rows in
Normal mode, with counts. All attached buffers automatically map j/k, gj/gk
and Up/Down to skip hidden fold rows, including ordinary Markdown and previews.
No extra mappings are needed. gj/gk preserve screen-line movement through soft
wraps; raw/disabled views, operators and Visual mode stay native. on.attach can
override the buffer-local defaults.
:Inkstone move_down / move_up and the corresponding Lua functions are also available.

LINKS
Normal-mode h/l skip hidden URL text and delimiters inside displayed links,
including counts such as 2l. Raw views, operators and Visual mode stay native.
Defaults are buffer-local and can be overridden in on.attach.
<Plug>(InkstoneMoveLeft) / <Plug>(InkstoneMoveRight), :Inkstone move_left /
move_right and the corresponding Lua functions expose the same movement.
Browser text fragments (#:~:text=...) containing unmatched literal opening
parentheses are recovered as single-line HTTP(S) links without changing source.
Long hidden URLs use displayed-width wrapping on conceal-aware Neovim builds;
older builds retain the native wrapping limitations.

TABLE VIEWS
:Inkstone toggle_table cycles table -> list -> chart -> table under the cursor.
:Inkstone toggle_list switches table/list; :Inkstone toggle_chart switches
table/chart. Nonnumeric tables skip charts. Numeric series must share units.
Charts use rsvg-convert and Snacks, with text bars when those are unavailable.
pipe_table.view chooses the default; pipe_table.chart.kind is bar or line.
:Inkstone toggle_view chooses the table, fold or media at the cursor.
Normal-mode Ctrl+i invokes this action in attached buffers. Tables cycle
table -> list -> chart -> table (nonnumeric tables skip chart). Closed parent
folds open before hidden children are selected. Otherwise tables take priority
over enclosing folds, and media must be on the cursor row. Without a target,
or with Inkstone disabled, Ctrl+i retains native jump-forward movement/counts.
Terminals that encode Ctrl+i as Tab also use Tab for this mapping. Buffer-local
overrides can be set in on.attach.
<Plug>(InkstoneToggleView), <Plug>(InkstoneToggleTable),
<Plug>(InkstoneToggleList) and <Plug>(InkstoneToggleChart) are mappable actions.
Table view state follows edits; source data is never rewritten.

KITTY TYPOGRAPHY
Kitty >= 0.40 and Neovim >= 0.12 support actual text sizing through OSC 66.
typography.enabled='auto' uses tmux's cached client_termtype or, outside tmux,
a positive terminal reply. No terminal identity query is sent through tmux. Default heading
sizes are {2, 1.5, 1.25, 1, 1, 1}; literal single-line <small>text</small> uses
typography.small=0.8. :Inkstone typography toggles it for the current buffer.
Active typography reserves blank native cells; it does not keep a second,
normal-size copy underneath. Disabling typography restores ordinary rendering.
Idle text is not resent. After an external tmux redraw, :Inkstone refresh restores
the overlay. typography.recovery=true opts into periodic 250ms replays; the
default is false because repeated fractional-text output can flicker.
Outside tmux, detection temporarily guards ttimeout/ttimeoutlen for up to 1.2s,
then restores them, so split replies do not become mapped input at short timeouts.
Stock tmux requires allow-passthrough on or all. Inkstone accounts for pane
offsets and checks window/zoom visibility even with allow-passthrough=all. Hidden
panes cannot paint or erase text in the destination view; visible inactive
panes retain their typography. Focus return or the next native redraw restores it.
It repairs visible sized text after every completed Neovim redraw. Identical
native blank cells can still erase multicells; source-row notifications and cell
equality do not prove the overlay survived. Cursor-only updates do not erase intact
overlays. Command-line input and non-overlapping fzf/float updates leave other
headings intact. Popup windows take precedence only where they overlap; recovery
replays unchanged glyphs without first clearing them. Original source returns according to
anti_conceal. Existing paragraph/table replacements retain their
own layout. Unsupported terminals keep normal text. See demo/rich.md and
doc/rendering-features.md for examples and limits.
See doc/rendering-features.md for all options and graphics ownership with Snacks.
For auto-cursorline.nvim integration, update both plugins. Cursorline is
temporarily suppressed on shown typography rows; body/source rows retain its
normal delayed behavior through window-scoped row highlights. This avoids native
cursorline option redraws while typography is shown. Explicit screenline mode
keeps native wrap semantics. Buffer/tab changes and window closing clear old
placements before the new view draws. Other suppression owners are preserved.

LATEX
Install utftex or latex2text (Arch: python-pylatexenc). Markdown formula ranges
allow Unicode conversion without a separate LaTeX parser. latex2text 2.x uses
mostly flat text; utftex supports multiline layouts. Kitty math images are not
part of this converter path. Centered standalone math blocks replace their raw
source; above/below positions retain source plus preview. Converter changes
invalidate old output. Try demo/latex.md with demo/rich_init.lua.

PERFORMANCE
Code body decoration is viewport-bounded. Width summaries invalidate on edits
and display-width options; their cache is bounded and released on buffer wipe.
The initial block scan and native Tree-sitter parsing can still scale with
block/document size. See doc/performance.md for measured scope and benchmarks.

DISPLAY COMPATIBILITY
>
  require('inkstone').setup({
    display_compat = { enabled = 'auto', kana = true, replacements = {} },
  })
<
Kitty environment variables enable the default display-only workaround: halfwidth
kana plus voiced/semi-voiced marks are painted as fullwidth equivalents in the
same Neovim cells (e.g. ｶﾞ -> ガ, ﾊﾟ -> パ). All 112 kana/mark pairs are covered;
pairs without a precomposed character use a fullwidth base and combining mark.
Source buffers, search, yank and saved text retain the original bytes. Stock
tmux is supported; neither terminal patches nor raw OSC output are used.

enabled=true forces this on; false disables it. kana=false removes the builtin
rules. replacements maps individual display clusters to equal-width text; rules
containing controls or changing width are ignored. Rendered rows and virtual
wrapped rows are handled, while concealed text remains hidden. Anti-conceal and
disabled rendering restore source appearance. Unprocessed scratch buffers and
arbitrary Unicode width disagreements are outside this feature's scope.
